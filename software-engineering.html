CS Fundamentals / Deep Dive

Sliding-window statistics

Instead of recomputing a user's rolling mean and variance from every value in the window, the tracker keeps the state needed for the next update. That changes a per-message O(window) recomputation into O(1) amortized maintenance, while still allowing the baseline to evict stale observations.

O(window) → O(1) amortized

Aho-Corasick

The phrase matcher builds a trie once and adds failure links so one scan can continue through multiple patterns. That matters when dozens of urgency or manipulation phrases need to be checked against every message without rescanning the full text for each phrase.

O(phrases × text) → O(text + matches)

Bounded min-heap

When the application only needs the riskiest K users, fully sorting N users is unnecessary work. A bounded min-heap keeps the current top K and evicts the weakest candidate whenever a better one arrives, reducing ranking cost from a full O(N log N) sort.

O(N log N) → O(N log K)

LRU cache

Baselines should not grow forever just because the service stays alive. An LRU cache keeps the most recently used entries while evicting old ones once the fixed capacity is reached, giving predictable memory behavior rather than an ever-growing in-process store.

bounded memory footprint

Composite + Visitor

Netlist Parser models nested circuits as a composite object so the caller can reason about a subcircuit as a whole. Visitor then moves analysis operations outside the data hierarchy, so adding a new analysis pass does not require rewriting every component class.

decouple data model from analysis

Operating-system-facing code

The parser is a native command-line process: it receives a file path, performs filesystem I/O, builds an in-memory object graph and exits with an error status when parsing fails. The important lesson is not “I called ifstream”; it is that application behavior depends on process arguments, files, memory and error handling at the OS boundary.

CLI · file I/O · process lifecycle · memory

Atomic Redis rate limiting

Sentinel moves the check-and-update sequence into one Lua script. ZREMRANGEBYSCORE, ZADD and ZCARD happen as one Redis-side operation, avoiding a race where two concurrent requests could both observe the same old count and both be admitted.

one atomic round-trip

Performance benchmarking

The benchmark project uses JMH rather than naive timers to account for JVM warmup and JIT behavior. Across 100K to 10M integers, bucket sort consistently delivered about 3.2× the throughput of TreeMap sort for the chosen bounded range.

~3.2× throughput · n ≤ 10M
